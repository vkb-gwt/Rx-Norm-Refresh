# Rx-Norm-Refresh

This repository documents the monthly procedure for refreshing RxNorm drug codes.

## Files

- `rxnorm_refresh.sql` - SQL workflow for identifying new RxNorm drug codes to add and existing codes to retire.

## Process summary

1. Build a temporary current-month RxNorm view from the source reference tables.
2. Identify RxNorm codes that are new and should be appended.
3. Insert those new codes into the `rxnorm_drug_code` reference table.
4. Identify active codes that are no longer present in the latest source data.
5. End-date the existing active rows for the expired codes.

## Notes

- The procedure assumes `ref_id` is generated by the destination table and therefore omits it from the insert statements.
- The `note` field is left `NULL` unless your environment requires a specific value.
- The refresh-period parameters derive both the addition start date and the retirement end date from the same execution month so a single run stays temporally consistent.
- The retirement effective end date is derived as the last day of the previous month via the `refresh_parameters` view so the prior record remains active through that date.
- When multiple preferred RxNorm terms map to the same NDC, the script keeps one deterministic description using `SCD`, `SBD`, `GPCK`, then `BPCK` precedence.
